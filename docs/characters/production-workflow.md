# Amit Photos — תהליך הפקה שבועי

## מצב התהליך

ה־GitHub Action `.github/workflows/amit-character-ads.yml` בוחר רעיון חדש מתוך `data/campaigns/amit-photos/plan.json` בכל יום שני ב־08:15 UTC, ויוצר קובץ בריף להורדה בלשונית Actions. אפשר לבחור רעיון ידנית ב־`Run workflow` באמצעות מזהה כגון `level_sunset`. פעולה זו קוראת נתונים בלבד, ואינה צורכת קרדיטים, מפרסמת תוכן או משנה את האתר.

**אישור פרסום:** יצירת בריף או טיוטת MP4 לעולם אינה שולחת אותה לרשתות. לפני הפצה עמית צופה בקובץ הסופי, בודק את נוסח הפוסט ואת הקישור הלחיץ, ומפעיל בעצמו את `distribute-video.yml` מתוך חשבון `erezfamily-cmyk`. הפעולה דורשת את ערך SHA-256 של אותו MP4 ובודקת אותו מחדש לפני העלאה. שינוי אפילו של בית אחד בקובץ מבטל את האישור. אין schedule לפרסום סרטונים: `reels-post.yml` הפך לידני, ו־`reel-maker.yml` יוצר טיוטה ללא פרסום. בשני מסלולי הפרסום של Reel קיים נדרשים החשבון של עמית ו־SHA-256 של הקובץ שנצפה. אין בכך שינוי בפרסום פינים או תהליכי תוכן אחרים.

קובץ `src/campaign_ads.py` מרכיב סרטון טיוטה מסרטון מקור מאושר ומחמש הקלטות MP3. הגרסה הנוכחית **אינה** מייצרת אוטומטית שוטים וקריינות באמצעות API. חיבור מלא ל־Higgsfield/Runway/ElevenLabs דורש אישורי API נפרדים, בחירת קול עברי, מסגרת קרדיטים וניסוי ראשון מאושר. אין להעתיק סודות למאגר. חיבור האפליקציות בשיחה אינו מספק אוטומטית סודות ל־GitHub Actions.

## ממפתחים ועד סרטון

1. **רעיון:** פותחים את בריף השבוע מן ה־Action, או מפיקים מקומית: `python3 src/campaign_ads.py plan --concept level_sunset --date 2026-10-10 --output brief.md`.
2. **צילום אמיתי:** מאתרים צילום רלוונטי ב־`/api/photos` ובגלריה הציבורית. מתעדים מזהה וכתובת מקור; מאשרים הרשאות שימוש. מכניסים אותו בשוט השלישי. אין להחליף אותו בתמונה מדומיינת המוצגת כצילום של עמית.
3. **שוטים:** משתמשים בתמונת הייחוס המאושרת של פקח הפריים כעוגן ב־Higgsfield/Kling 3.0 או Runway. יוצרים ארבעה שוטים, בערך 3.75 שניות כל אחד, ללא כיתוב, URL או קריינות מוטבעים. מחברים אותם לקובץ `source.mp4` של כ־15 שניות ביחס 9:16. שומרים פרומפט, מודל, תאריך ומזהה יצירה.
4. **קול:** מקליטים את חמש שורות הקריינות המופיעות בבריף בקול גברי עברי עקבי. בפיילוט השתמשנו ב־Runway עם Benjamin / `eleven_v3` / `he` / מהירות 0.95; בודקים את אותו הקול ידנית לפני חיבור API. שומרים `male1.mp3` עד `male5.mp3` בתיקיית `audio/`.
5. **הרכבה:** מתקינים `ffmpeg`, `ffprobe`, `DejaVuSans-Bold`, Python, `Pillow` ו־`reportlab`, ואז מריצים:

   ```bash
   python3 src/campaign_ads.py render --concept level_sunset \
     --source source.mp4 --audio-dir audio --output draft.mp4
   ```

   ההרכבה קובעת כתוביות RTL, שקופית סיום עם `amitphotos.com`, QR לקישור עמוק עם UTM, ופס קול. לכל ארבעת השוטים זמני התחלה 0, 3.75, 7.5, 11.25 שניות. השוטים עצמם חייבים להתאים לתזמון; הקוד אינו עורך אותם לפי תוכן.
6. **בדיקה:** צופים בכל הטיוטה בטלפון עם ובלי קול. בודקים דמות עקבית, היגוי עברי, טקסט בלי ג׳יבריש, צילום אמיתי, URL ו־QR. סורקים את ה־QR ובודקים שהוא פותח את הנתיב המתאים ב־`amitphotos.com`. מעתיקים את הקישור מן הבריף לתיאור הפוסט, כי טקסט בתוך MP4 אינו לחיץ. שומרים את ערך SHA-256 שהפקודה מדפיסה, ומאשרים רק את הקובץ הזה.
7. **פרסום ידני:** אחרי אישור, מפעילים ב־GitHub Actions את `📱 הפצת סרטון באישור עמית`, מזינים כתובת MP4 ציבורית ב־`https://amitphotos.com` או שם קובץ מתוך `video/`, את ה־SHA-256 של הקובץ שאושר ואת נוסח הפוסט המאושר עם הקישור מהבריף. אם הקובץ שהמערכת קוראת שונה מן הקובץ שנצפה, הפעולה נכשלת לפני פנייה לשירותי פרסום. במסלול Reel ותיק אפשר להפעיל `Instagram Reel — approved video only` רק לאחר בדיקת `reels_output/latest_reel.mp4` ו־`data/latest_reel.json` והזנת SHA-256 מתאים. אין ללחוץ `Run workflow` לפרסום לפני צפייה בקובץ.
8. **למידה:** מתעדים הופעות, שלוש שניות צפייה, השלמות, כניסות לפי `utm_content`, `photo_view` או `guide_request_success`. בשבוע הבא משנים רכיב אחד על סמך התוצאות.

## חיבור עתידי לייצור אוטומטי מלא

| רכיב | חיבור נדרש | בדיקת קבלה לפני הפעלה |
| --- | --- | --- |
| שוטי דמות | API של Higgsfield Kling או Runway; אישור תקציב נפרד | שתי יצירות עם אותו פנים ולבוש; בלי טקסט פגום |
| צילום אמיתי | קריאת רשומות פעילות מ־`/api/photos` עם מזהה ורישיון | השוט השלישי תואם צילום ציבורי זמין |
| קול עברי | API וקול גברי מאושר התומך בעברית | חמישה קבצים, בדיקת היגוי ושיוך נכון |
| תור עבודה | מגבלת יצירות לשבוע, תקרת הוצאה, retries ומניעת כפילויות | כשל עוצר ומדווח, בלי חיוב חוזר בלתי מוגבל |
| הרכבה והפצה | `campaign_ads.py` וטיוטת פוסט עם UTM | אישור אנושי לפני פרסום; כיבוי ברירת מחדל |

מגדירים את המפתחות כ־GitHub Secrets רק אחרי בחירת שירותים, תקרה ובדיקת חשבון API. מפרידים את תהליך זה מ־`reel-maker.yml`, `reels-post.yml` ו־`distribute-video.yml`, שעשויים לעבוד עם נכסים וערוצי פרסום אחרים. אין לחבר הפצה אוטומטית לפני שהניסוי החדש מאושר.

## שמירת חומרים

לכל סרטון שומרים `brief.md`, קובץ צילום מקור/מזהה, תמונת דמות מאושרת, פרומפטים, `source.mp4`, חמש הקלטות, `draft.mp4`, קישור UTM ונתוני מדידה. אין להכניס קובצי מדיה גדולים או מפתחות API ל־Git. הקבצים במאגר הם מפרט ותהליך בלבד.
